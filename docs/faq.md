# 常见问题

## 提示缺少 python3-yaml 或架构不兼容

确认使用本仓库新版 IPK，当前包不依赖 `python3-yaml`。仅支持 x86_64 和 opkg；不能通过忽略架构依赖来安装 ARM、MIPS 或 apk 固件。缺少其他依赖时检查固件软件源，勿混装不同 OpenWrt 大版本的软件包。

## LuCI 出现 500 或缺少模板

当前版本使用 LuCI 自带 CBI 模板，不依赖旧的 `ikuai_bypass/config.htm`。确认安装了 `luci-compat`，退出重登 LuCI，并确认没有混用旧包的控制器/表单。若仍有问题，提交完整报错、固件版本和安装包版本，先删除账号密码等隐私。

## 规则已经同步，网站仍访问不了

依次检查：OpenWrt 自身代理与 DNS → 爱快对应 WAN 网关与连通性 → 规则源地址组是否包含终端 → 实际连接命中的出口 → 终端 DNS、私人 DNS/安全 DNS与缓存。能访问某个网页不代表 WhatsApp 登录、视频和通话链路均已正常。

## Android WhatsApp 一直“正在连接”

将“私人 DNS”明确设为“关闭”，重连 Wi-Fi 并强行停止后重开 WhatsApp。确认 DNS 为计划下发的地址，代理软件的端口范围包含应用所需连接。附加功能不会代替节点配置或自动修改手机设置，详见 [WhatsApp 文档](whatsapp.md)。

## 更新失败会不会清空旧规则

4.4.110-9 起，LuCI 单次同步与 init 定时服务都有订阅保护。下载失败或空/非法列表不会交给核心执行替换。原始核心直接运行会绕过此层，详见[保护范围](subscription-guard.md)。需要有意删除规则时使用显式清理。

## 保存后为什么没立即改变规则

普通配置保存后需重启服务或执行单次更新。WhatsApp 选项保存后先预览，再点击同步，或重启服务。`cronAft` 启动时不会立即更新普通订阅，要等下个计划时间。

## 覆盖升级后定时服务未运行

升级会停止服务并关闭自启。核对原配置被保留后，在 LuCI 重新启用自启、启动服务。不要将 `.yml-opkg` 默认模板直接覆盖已配置的文件。

## 应把问题提交给谁

本包的 LuCI、包装、订阅保护和附加功能问题提交到本仓库。底层核心行为先参考[原作者文档](https://joyanhui.github.io/ikuai-bypass/)，复现时注明使用了非官方包装版。提交日志前删除密码、私有链接、IP、会话和配置备份。
