# Telegram / ChatGPT 应用增强（4.4.110-10）

本页说明程序内的可选功能。升级不会自动开启新选项，也不会改动爱快全局主备 DNS 或 DHCP 下发的 DNS 地址。

## 为什么只订阅 GFW 还不够

Telegram 客户端会直接连接数据中心 IP，不能仅依靠域名分流。ChatGPT 除主站外，还使用登录、静态资源、文件和 WebSocket 等域名。另一个常见问题是：旁路由自身 DNS 正常，但收到的 UDP 53 查询被直接放行，终端仍拿到错误地址；即使后续连接已走代理 WAN，也连接不到正确服务器。

本功能组合解决这三类配置问题。IPv4 应用规则使用现有上游核心处理，全部经过订阅保护层，按原更新计划重新下载；DNS 防泄漏是本机防火墙配置，不是修改爱快主 DNS。

## 启用前的 DNS 条件

本功能不自动修改爱快全局 DNS 或 DHCP。终端应使用已经验证的解析方案；例如由 DHCP 下发公共 DNS，让需要分流的查询经过代理 WAN。如果终端仍向爱快网关查询，而网关自身返回了错误解析，需要先修好该链路，不能指望 OpenWrt 截获未送达它的请求。需要 DHCP 下发 DNS 时，可使用既有 WhatsApp 附加功能的可选 DHCP 设置，或在爱快管理界面单独配置。

## 在 LuCI 启用

进入 **服务 → iKuai Bypass → Telegram / ChatGPT**。

1. 在普通“域名分流”页先配置一个作为基准的规则，例如 `gfw`，填写实际代理 WAN、源地址或爱快源 IP 分组。
2. 分别开启“Telegram 完整 IPv4 分流”“ChatGPT 域名补全”，选择它们跟随的域名规则。
3. 如需防止已送到 OpenWrt 的普通 DNS 请求绕过本机解析，开启“DNS 入口防泄漏”。默认来源区域 `lan`，目标地址自动读取本机 LAN 地址，服务端口默认 `53`。
4. 本机使用 PassWall2 且需要完整 TCP 端口接管时，可开启“管理 PassWall2 全 TCP 端口”。仅操作已启用的 PassWall2，不自动启用插件或更换节点。使用其他代理软件时保持此项关闭，并在对应软件核对端口范围。
5. 保存，点击“预览应用增强计划”。核对 WAN、源范围、DNS 来源区域/本机端口和有效模式。
6. 停止定时服务，点击“立即同步（含应用规则）”；刷新日志，确认订阅通过保护及爱快更新成功。
7. 核对爱快规则和终端使用结果，再启动定时服务、开启自启。以后改基准规则的 WAN 或源分组，保存并重启服务，应用规则自动跟随。

保存只保存参数。单次同步和服务启动时会应用本机 DNS/端口设置；`cronAft` 启动后普通订阅仍等待下次计划，因此首次应执行单次同步。诊断终端地址保存后可使用“诊断 Telegram / ChatGPT 连接”。

## 生成哪些规则

| 选项 | 生成/管理内容 | 可修改来源 |
| --- | --- | --- |
| Telegram | `TGClient` IPv4 分组订阅、同 tag 的爱快端口分流，协议不限、通讯端口不限，源范围/出口跟随基准 | [Telegram 官方 CIDR 列表](https://core.telegram.org/resources/cidr.txt)，混合列表取 IPv4 |
| ChatGPT | `ChatGPT` 域名规则，源范围/出口跟随基准 | [本仓库纯文本域名列表](../rules/chatgpt-domain-list.txt)，界面可改为自己的链接 |
| DNS 入口防泄漏 | OpenWrt 的 `firewall.ikb_dns_guard`，名称 `IKB-LAN-DNS-Guard`，将来源区域的 IPv4 TCP/UDP 53 转至本机 LAN DNS 服务 | 本机 LAN 地址自动读取；区域和端口可在界面修改 |
| PassWall2 全 TCP | 将 PassWall2 TCP 代理端口设为 `1:65535`，保存接管前原值 | 仅在该项开启、PassWall2 已启用时操作 |

`TGClient`、`ChatGPT` 是该功能保留的 tag。若原始配置已存在这些同名条目，会要求显式接管；先核对预览再勾选。已有同名 DNS 规则也须显式接管，接管后由本功能负责移除。

应用规则在运行时生成，不写进普通规则数组，也不会覆盖原 YAML。它会按需组合有效模式，但只保留基础模式原本选中的模块，避免顺带启用模板里未选模块的 IP 或端口示例。预览可看到“基础模式 → 有效模式”。

## DNS 入口保护的边界

必须先确认本机 DNS/代理正常工作。启用或更改目标前会检查本机 DNS 服务，失败则不应用防火墙变更。此选项只处理进入所选 OpenWrt 防火墙区域的普通 53 端口请求；爱快仍负责把应分流的查询和流量送到这台 OpenWrt。它不修改全网 DNS，不处理客户端自带的 DoH、DoT 或其他加密 DNS。

默认 `lan` 是本机代理侧 LAN，不是把所有爱快内网 DNS 统一改成 OpenWrt。若自定义区域，需确认区域存在且允许访问本机 DNS。IPv6 分流、IPv6 DNS 入口及应用语音通话不在本次 IPv4 验证范围。

Android 私人 DNS 明确选“关闭”，浏览器安全 DNS 也应结合路由方案核对。DNS 修复后，必要时重连 Wi-Fi并彻底关闭重开应用，清除旧解析/连接的影响。

## 关闭、恢复与清理

- **Telegram / ChatGPT 开关关闭：** 保存并停止旧服务后，不再生成/更新对应规则；爱快中已同步的规则不会自动删除。需要移除时，保持服务停止，在“运行与日志”按 `TGClient` 或 `ChatGPT` 显式清理，然后重新启动服务。若原始配置中仍有同名普通条目，它们仍按普通配置执行，应自行一并核对。
- **DNS 保护关闭：** 下次同步/启动时移除本功能管理的 DNS 规则。显式接管的同名规则也属于管理范围。
- **PassWall2 全 TCP 关闭：** 恢复接管前的端口列表；如果接管前本来就是全端口，恢复后仍是全端口。PassWall2 已关闭时只恢复配置，不自动启动它。
- **外部修改保护：** 手工改变本功能管理的防火墙或 TCP 端口后，程序拒绝覆盖，并在日志提示。先核对备份与实际配置，不要随意删除状态文件绕过检查。

本机状态保存在 `/etc/ikuai-bypass/applications-dns-state.json`、`applications-proxy-state.json`，变更前备份在同目录 `backups/`。升级/迁移应私下保存整个配置目录；不要把一台机器的状态文件复制到另一台，或将备份上传公开仓库。

## 验证结果和故障判断

已验证 Telegram IPv4 直连 IP 分流、ChatGPT 补充域名及 DNS 防泄漏组合可修复客户端访问。测试手机已实际完成 Telegram 联网和 ChatGPT 提问收答；本结果不代表所有节点、系统或语音视频通话都已验证。

新功能覆盖开关、WAN/源分组跟随、重复运行、闲置示例不激活、同名接管、DNS 健康检查、失败回滚和外部改动拒绝的测试；真实核心还测试了生成规则、出口切换不重复及空订阅保留旧规则。

`curl chatgpt.com` 返回 403 且带 `cf-mitigated: challenge` 表示站点发起网页验证，不能仅凭它判定代理失败或成功。应查看实际客户端是否能发送问题、解析是否异常，以及连接是否命中预期 WAN。官方参考：[OpenAI 网络建议](https://help.openai.com/en/articles/9247338-network-recommendations-for-chatgpt-errors-on-web-and-apps)。
