# WhatsApp 附加功能（4.4.110-8）

安装 IPK 后，在 LuCI → 服务 → iKuai Bypass → WhatsApp 附加功能配置。默认关闭，安装本身不会修改爱快规则。

1. 先完成基本设置中的爱快地址、账号和密码。在“域名分流”中配置 GFW 规则、出口线路以及源地址组。
2. 打开附加功能，“跟随域名规则标识”填写该规则的 tag，例如 `gfw`。它自动读取该规则的 WAN 和源地址组。其他路由改为 WAN2、WAN5 时无需重复填写。
3. 按需开启“配置所选 WAN 的多线路 DNS”。线路 DNS 留空读取本机 `network.lan.ipaddr`，例如 `192.168.88.1`。必须先确认本机代理和 DNS 可用。此项只管理所选线路，不改爱快全局主备 DNS。
4. 按需开启 DHCP 下发 DNS，默认 `119.29.29.29`、`223.5.5.5`。可显式填写爱快 DHCP 范围 ID，避免源地址组排除网关或旁路由后无法自动匹配整个地址池。固定 DNS 的终端需自行设置。
5. 先保存设置，再使用“预览 WhatsApp 同步范围”核对已保存设置，确认后点击“同步 WhatsApp 配置”。预览本身不写入爱快。重启 ikuai-bypass 服务也会同步已保存的附加设置。
6. Android 设置 → 私人 DNS：明确选“关闭”，不要选“自动”。重连 Wi-Fi、强行停止 WhatsApp 后测试。该终端设置无法由路由程序代改。

程序创建 `IKBWhatsApp` 域名规则，包含 `whatsapp.com`、`whatsapp.net`、`wa.me`，源范围和出口跟随指定规则。已有完全相同三域名用途规则时，必须显式开启接管；接管前保存原规则。不会导入过时的 WhatsApp IP 分组，不会强制全部终端流量走代理。

同步前备份位于 OpenWrt `/etc/ikuai-bypass/backups/whatsapp-addon-*.json`；管理状态位于 `/etc/ikuai-bypass/whatsapp-addon-state.json`。关闭功能、保存并点击同步（或重启服务），会删除本功能创建的规则，恢复接管前的线路 DNS、DHCP 和域名规则。请保留状态文件，尤其在升级或迁移恢复时。外部修改过本功能管理的规则时会停止同步，避免覆盖人工修改。

“诊断终端连接”需先保存具体 IPv4 地址，可查看 443、5222、5223、853 的连接及出口。若存在 853 连接，应核对私人 DNS。代理软件如仅代理指定 TCP 端口，还需确保 WhatsApp 使用的端口包含在代理范围内；本功能不修改 PassWall、OpenClash 的节点和端口设置。登录成功不能代表语音、视频通话已经验证。

可覆盖安装同系列旧版 IPK，配置文件由 opkg 保留；新增附加功能字段在 LuCI 显示默认值。批量部署时，每台必须填写自己的爱快账号、GFW 出口和源分组。IPK 内不包含现场密码。

验证：Linux/OpenWrt 上运行 `python3 -m unittest discover -s tests -v`。覆盖预览无写入、重复同步、WAN 切换、关闭恢复、接管恢复、外部改动拒绝及故障回滚。Windows 不提供 flock，测试应在 Linux 上执行。
