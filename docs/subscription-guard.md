# 订阅更新保护（4.4.110-9）

LuCI 的“立即更新一次”和 init/procd 定时服务统一经过订阅保护层，无需额外开启。

每个订阅的更新顺序：完整下载到内存 → 校验响应和列表 → 将本次已验证的内容交给上游核心 → 编辑或新增规则 → 核心清理该订阅多余的旧分片。校验后不会再次向 GitHub 下载同一份内容，因此不存在“预检成功，真正更新时第二次下载失败”的窗口。

以下情况拒绝更新对应订阅，保留它原有的爱快规则：连接失败、超时、HTTP 错误、空列表、仅注释或没有匹配地址类型的条目、HTML/JSON 错误页、非法列表内容、明确的响应长度不完整或超过 32 MiB。IPv4、IPv6 混合订阅会选取对应地址类型；域名列表去除注释、重复项，并兼容核心跳过含下划线条目的行为。

保护按订阅生效：一个订阅失败不阻止其他正常订阅更新。定时失败后保留旧规则，下个计划时间再次下载，不会拿空数据替换。LuCI 任务日志中的 `GUARD:REJECT` 表示拒绝此次订阅；单次更新出现这种拒绝会返回非零退出码 2，避免核心本身退出 0 被误认为完全成功。长期定时进程保持运行，通过日志记录每轮拒绝。

这是下载与列表校验保护，不是爱快写入事务。爱快接口写入中途失败的完整回滚，以及语法正确但内容错误、没有长度信息却提前结束的有效非空列表，不在本次保证范围内。若确实要清空规则，应使用已有的显式清理功能，不以空订阅实现。直接运行原始 `/usr/bin/ikuai-bypass` 会绕过保护；使用 LuCI、init 服务或 `/usr/libexec/ikuai-bypass-guard /etc/ikuai-bypass/config.yml -r once`。

保护器仅监听随机本机回环端口，使用随机路径，临时配置权限 0600、目录 0700，停止后清除临时配置。原始配置及订阅链接不被覆盖，下载仍使用原配置中的代理方式。

已执行：4 项校验单元测试、实际上游二进制的 8 种模拟下载场景，以及有效/空列表的连续多轮 cronAft 定时测试。所有故障场景均无 add/edit/del 请求，有效列表按先下载再更新顺序处理。测试连接 127.0.0.1 模拟接口，没有删除现网规则。
